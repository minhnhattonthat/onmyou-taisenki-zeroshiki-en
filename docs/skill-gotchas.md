# Skill gotchas

One line per gotcha: the reference file it belongs in, then the fact.

- SKILL.md Step 0: in an Orca worker session the plugin was enabled but neither its skill nor its hooks loaded; adding the `hooks` block (stable `$HOME/.claude/plugins/marketplaces/...` path) to `.claude/settings.json` took effect live in the same session.
- emulator-qa.md: the guard hook blocks a whole Bash call whose text merely contains `sed -i` (even inside a piped JSON test), so the rest of that call (e.g. an `rm`) never runs.
- graphics.md §Survey: `codex exec -s read-only -i sheet...` works as the read-only sweep reviewer (~57 sheets per call); without "write in English" it answers in Japanese.
- platform-gba.md: Mesen `on_read` probes never show glyph reads when the game copies glyphs with BIOS CpuSet into a RAM buffer; trace the draw call's arguments in disassembly instead.
- emulator-qa.md §Debug tool: Mesen GBA Lua `emu.setState({["cpu.r4"]=X})` inside an exec callback changes the register live, so a script-engine game can be warped by pointing its "start script" routine at bytecode written to free EWRAM (no ROM patch, works on any build).
- emulator-qa.md §Debug tool: a `--var` key with an underscore (`until_op=`) silently failed a `(%w+)=` Lua pattern; use `[%w_]+`.
- emu.py: `--mash` starts as soon as the route queue empties, including a route a `--script` queued with L.press, so mash runs reach a warp's scene earlier than unmashed ones (frame numbers differ between runs).
- emu.py: `--sheet` writes only the first 15-16 frames when a run has more shots; run `sheet.py DIR --from --to` for the rest.
- pipeline.md §Identity: a byte-identical repack doesn't prove the pointer lists; also build a relocate-everything variant (vacated rooms 0xFF) and warp every scene with a ROM-read probe flagging reads of vacated rooms. Here it caught an empty string pointed at inside another string's NUL padding and a script that code finds by scanning forward from its slot.
- lua/probes/watch.lua: it logs once per PC, so a memcpy or copy loop hides every later address; for 'who still reads old text' log once per address instead (tools/debug/romreads.lua).
- platform-gba.md: Shift-JIS games can park extra (JIS level 2) kanji in unused font cells at Cyrillic/Greek codes (here 0x8440..0x8459): a text dump shows `Ф麟` for 麒麟. Render those cells from the font and write the readings into the dump's notes before translating.
- platform-gba.md: keystone (Thumb) can't resolve a label's address for you; put `b entry1` / `b entry2` at the blob start so each entry sits at a fixed offset (0, +2). A 16-byte `bx pc` + ARM `ldr ip,[pc]; bx ip; .word target|1` thunk reaches code past the 4 MiB BL range (ARMv4T `ldr pc` doesn't interwork).
- emulator-qa.md (Debug tool): a warp scene reached through boot-route dialogue (mashing A through an intro) needs a bigger frame budget/deadline on the marker build: VWF marker lines are ~3x longer than the Japanese, so typing takes ~3x the frames (tutorial_battle timed out at 15000).
- emulator-qa.md / platform-gba.md: to list every text renderer, hook *reads of the font data* (log distinct pc + lr per scene, tools/debug/glyphreads.lua) instead of tracing each box: 44 scenes gave 3 code paths in one run, and a renderer showing only BIOS CpuSet reads (pc 0x0B8E) copies whole glyph tiles.
- emulator-qa.md / platform-gba.md: font-data read hooks miss renderers that copy glyphs with BIOS CpuSet (the reader pc is the BIOS); hook the game's glyph *lookup* call instead (tools/debug/fontcalls.lua: 0x080059A0 with type 13, distinct lr): 7 call sites vs 3. Renderers that write glyph cells straight into VRAM need halfword read-modify-write for a VWF (a byte store lands in both bytes).
- platform-gba.md: keystone (Thumb) silently mis-encodes `adds rd, rn, #imm` with rd != rn and imm > 7 (3-bit field): `adds r2, r0, #15` left r2 unchanged and broke a whole screen. Use `adds rd, #imm8` on one register; tools/vwf.py `_asm` now rejects the bad form.
- pipeline.md (Marker build): once a renderer is VWF, a marker filled to the JP's pixel width has more *bytes* than the JP; a caller that copies text into a fixed stack buffer (here 28 bytes + the rest into 60 bytes for a 2-row battle box) overran it and garbled VRAM all over the screen. Check every renderer's callers for byte-count splits/buffers before widening marker text, and replace the split with a width-based one.
- pipeline.md (Width gate): name tags centred by character count shift left as English gets longer in characters than the JP (marker tag started off-screen); find the centring code and centre by pixel width before measuring tag budgets.
- pipeline.md (Width gate): a scene shot is often taken while the box is still typing, so a missing last glyph looks like clipping. Re-run from the scene's savestate (`emu.py --state-in S --frames 300+`) before calling a limit; here the battle window's row 2 really did clip 4 px earlier than row 1, while the dialogue "clip" was only typing.
- pipeline.md (Width gate): the page-wait icon (here an orb at x 226) is drawn over the last row, so the last line of a page needs its own, smaller budget (`last_px`); a stress line at the full width hides it because the icon only shows once typing ends.
- emulator-qa.md: a renderer probe that logs (routine, caller, string pointer) for every text renderer, mapped back to entry ids through the build's write log, gives the entry → box-variant map for the window data in one tour (`tools/debug/drawcalls.lua` + `tools/windows.py map`).
- platform-gba.md (keystone): `strb/strh/ldrb/ldrh rX, [sp, #n]` has no Thumb-1 encoding; keystone silently emits a 32-bit Thumb-2 `strb.w` that the GBA's ARM7 can't run (the game froze inside the new routine). Use `mov rN, sp` and a low-register base; `tools/vwf.py _asm` now rejects the pattern, like the `adds rd, rn, #imm>7` one.
- pipeline.md (Marker / non-text strings): a table of one-character strings can be lookup keys for other text (here each kanji of a super-move name picks a cut-in graphic by matching a 257-entry kanji table). Translating the names then breaks the cut-in: give that reader its own copy of the original table + strings (repoint its literal) and mark the key table keep_jp.
- pipeline.md (Width gate): a name-entry grid drawn through a map-line renderer packs letters with a plain VWF (cells no longer match the cursor index, old tab's glyphs left in unused cells); retarget only the grid's call to a fixed-cell variant that centres one glyph per cell.
- pipeline.md (Width gate): code that copies a default name into RAM may copy a fixed count of JP characters (here 2 halfwords); check the copy length when the English default is longer in bytes.
- emulator-qa.md: Lua probes that sweep the whole OAM need the shape/size table and 1D tile counts; tools/debug/oamall.lua does it and merges used tile ranges, vramfree.lua polls VRAM (catches DMA, which write callbacks may miss).
- pipeline.md (Checks / romdiff): `romdiff.py --writes` counts every logged write as allowed wherever it lands, so it can't catch a write to the wrong place; confine writes with a repo gate (tools/romgate.py: text writes only in their own room / pointer words, the rest inside an allowed-ranges file, no branch into a hook span).
- pipeline.md (Width gate): a fixed-cell OBJ drawer with a small-font mode (one 8 px tile per character) can also lay out its sprites by character count; a VWF that only replaces the big-font mode leaves English names spilling into the next field's tiles (here the party card showed "Kogen" + HP digits). Grep each drawer's size/mode argument at every call site, not only the toured ones.
- emulator-qa.md: a menu option that needs a save or link partner can't be warped to by input; measure its box by finding a twin call (same window-open arguments) whose box was measured.
- graphics.md / platform-gba.md: widening a sprite cell (OAM shape in the game's cell table) widens every sprite that uses that cell. The speaker-plate cell was shared with the party-card name row, whose 5 tiles were followed by HP digit tiles: the "Kogen 29" bug blamed on char-count layout was this. Before widening a cell, list every sprite create that uses it; give each its own tiles (vramfree.lua finds free ones).
- platform-gba.md: an English font with a 1 px outline colour shows that colour as a solid box where an OBJ palette maps it to black and the JP glyphs had no outline; strip the outline index in that renderer path.
- platform-gba.md: keystone assembles Thumb `nop` as the Thumb-2 hint 0xBF00, which the GBA's ARM7TDMI can't run; write `mov r8, r8` (0x46C0) for padding.
- emulator-qa.md: emu.py `--var AT=3500` arrives in Lua as a number, so `AT:gmatch` errors; wrap such vars in `tostring()`.
- graphics.md: vramfind.py matched the title-menu button tiles to scattered single tiles of a dedup tileset (0x1442xx, dup:N) while the real source was a contiguous 14-tile run elsewhere (0x224874); a VRAM write watch (valwatch lr/r0 at the BIOS CpuSet PC 0xB90) gave the true source in one run.
- emulator-qa.md: probes/watch.lua in read mode on a ROM range sees no BIOS CpuSet/DMA reads (0 hits for tiles the game did copy); watch the VRAM destination for writes instead and read r0 (source) at the BIOS PC.
- emulator-qa.md: emu.py drops a screenshot identical to the previous one, so a per-N-frames shot sequence on a static menu leaves only 1-2 files; that is expected, not a failed hook.
- platform-gba.md: keystone rejects GNU numeric local labels (`bge 1f` / `1:`) with KS_ERR_ASM_INVALIDOPERAND; use named labels.
- platform-gba.md (this game): sprite cell ids above 662 (bound literal 0x02960000 at 6 sites) are another resource type, so a sprite cell appended at id 994 silently drew nothing; give a fixed-width OBJ more tiles instead of a new cell.
